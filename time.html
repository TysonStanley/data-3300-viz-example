Each line tells a different story, and you can read all three in seconds:

  • Outdoor gear is seasonal: it peaks every summer and bottoms out every winter.
  • Smart home is steadily growing, more than doubling over three years.
  • Office supplies was flat, then dropped about 40% right when the site was redesigned. That’s a problem worth investigating.

In the table, the seasonal swing looks like noise, the steady growth is spread across 36 rows, and the drop is just one column of numbers getting a bit smaller partway down.

NoteData format for the grouped line plot

The table above is wide (one column per product line), but sns.lineplot() with hue= needs long data: one row per product line per month. Three years of monthly data for three product lines is 36 × 3 = 108 rows in visits_long.

Column Type Role in the chart
month date (datetime64, first day of each month) x: the time axis
product_line text: Outdoor gear, Smart home, Office supplies hue: one line per unique value
visits integer y

Two details matter:

  • month must be real dates, not text. In the wide table it’s stored as text like "2025-01". The “Site redesign” marker (pd.Timestamp("2025-01-01")) and the date-axis labels (mdates) only work on a true date column. Starting from text, convert with pd.to_datetime().
  • One row per group per time point. If a product line had several rows for the same month, lineplot() would average them and draw a shaded uncertainty band instead of a single clean line.

The keys of the palette dictionary must match the product_line values exactly. See the note below for converting wide data to long.

NoteWide vs. long data

## Data format for the grouped line plot
The table above is **wide** (one column per product line), but `sns.lineplot()` with `hue=` needs **long** data: **one row per product line per month**. Three years of monthly data for three product lines is 36 × 3 = 108 rows in `visits_long`.

| Column | Type | Role in the chart |
|---|---|---|
| `month` | date (`datetime64`, first day of each month) | `x`: the time axis |
| `product_line` | text: Outdoor gear, Smart home, Office supplies | `hue`: one line per unique value |
| `visits` | integer | `y` |

Two details matter:

- **`month` must be real dates, not text.** In the wide table it's stored as text like `"2025-01"`. The "Site redesign" marker (`pd.Timestamp("2025-01-01")`) and the date-axis labels (`mdates`) only work on a true date column. Starting from text, convert with `pd.to_datetime()`.
- **One row per group per time point.** If a product line had several rows for the same month, `lineplot()` would average them and draw a shaded uncertainty band instead of a single clean line.

The keys of the `palette` dictionary must match the `product_line` values exactly. See the note below for converting wide data to long.

## Wide vs. long data
Spreadsheets usually store time series **wide** (one column per group). `seaborn` wants data **long** (one row per observation, with a column naming the group), which makes `hue=` work. Converting is one line with `pandas`:

```{python}
#| echo: true
long = visits_wide.melt(id_vars="month", var_name="product_line", value_name="visits")
long.head(8)
```
